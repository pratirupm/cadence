Book one built a todo app for the terminal with a test before every behavior and a
Git commit after every working step. This book keeps the habit and changes the
boundary. The same task domain becomes a service: accounts, workspaces, recurring
tasks, reminders, an API, a sync client, webhooks, and a deployment.

You do not need to have finished book one if you know Rust ownership, structs,
enums, traits, `Result`, tests, and Cargo. A short recap is in the appendix.

## What you build

A task service called Cadence:

```console
$ cadence serve
$ cadence worker
$ cadence migrate
$ cadence user create --email you@example.com --name You \
    --password "correct horse battery staple" --verified
$ cadence-cli sync
```

The browser has workspaces, projects, tasks, filters, and live updates. The API
has scoped tokens and idempotent creates. The CLI works offline and resolves
conflicts. The worker delivers reminders and webhooks.

## How it is taught

Every chapter starts with a behavior, shows the failing test or the contract,
builds the smallest implementation, then explains the failure modes. The code is
the reference; the prose explains why it is shaped that way.
